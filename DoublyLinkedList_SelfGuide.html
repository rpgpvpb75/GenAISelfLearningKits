Step 1 of 4

Two pointers per node: next and prev

The kernel says“A doubly linked list is a chain of nodes where each node holds data, a next pointer and a prev pointer; head.prev and tail.next are NULL”
Kernel check. Accurate. Each node costs one extra pointer of memory compared with a singly linked list.
  • Each node has prev, data and next. The upper arrows follow next and the lower arrows follow prev.
  • head.prev and tail.next are NULL: those are the two ends.
  • The extra pointer costs memory, but every node knows both its neighbours.

Step 2 of 4

Building it as a series: three lines per element

The kernel says“Build it as a series: element 1 makes head and tail point to the new node, elements 2 to N do node.prev = tail, tail.next = node, tail = node, and the loop stops after element N”
Kernel check. Accurate. Order matters only in that tail must still point at the old last node while node.prev and tail.next are set; tail = node comes last.
  • Element 1: head == NULL, so head = tail = node and both its pointers stay NULL.
  • Elements 2 … N: node.prev = tail (link back), tail.next = node (link forward), tail = node (move on).
  • The loop stops after element N. Compared with a singly linked list, each element adds one extra line: the back link.

Step 3 of 4

Navigating both ways

The kernel says“It can be navigated in both directions: forward from head along next, or backward from tail along prev, each walk stopping at NULL”
Kernel check. Accurate. Starting from the nearer end halves the worst-case walk: node k takes min(k − 1, N − k) moves.
  • Forward: temp = head, then temp = temp.next until NULL.
  • Backward: temp = tail, then temp = temp.prev until NULL.
  • To reach node k, start from the nearer end: min(k − 1, N − k) moves.

Step 4 of 4

Deleting a node: fix two links

The kernel says“Deleting a node X fixes two links: X.prev.next = X.next and X.next.prev = X.prev, with head or tail moving when X is at an end”
Kernel check. Accurate, with the end cases spelled out: if X is the head there is no X.prev, so head = X.next; if X is the tail there is no X.next, so tail = X.prev. Given a pointer to X, no walk is needed.
  • To remove X: X.prev.next = X.next (the forward link skips X) and X.next.prev = X.prev (the backward link skips X).
  • If X is the head, head = X.next instead. If X is the tail, tail = X.prev instead.
  • Because X knows both neighbours, no walk is needed once you hold X.
