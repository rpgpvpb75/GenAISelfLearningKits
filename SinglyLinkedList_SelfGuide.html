Step 1 of 4

Nodes, next pointers, head and NULL

The kernel says“A singly linked list is a chain of nodes where each node holds data and a next pointer to the following node; head points to the first node and the last node's next is NULL”
Kernel check. Accurate. An empty list is head = NULL.
  • A node has two parts: the data (a song name) and next, the address of the following node.
  • head points to the first node. tail points to the last node, whose next is NULL.
  • Nodes need not sit side by side in memory; the next pointers are what hold the chain together.

Step 2 of 4

Building the list as a series: element 1, 2, 3 … N

The kernel says“Build the list as a series: element 1 makes head and tail point to the new node, elements 2 to N do tail.next = node then tail = node, and the loop stops after element N”
Kernel check. Accurate, with one qualifier from your notes: element 1 must test head == NULL. Testing head->next == NULL crashes on an empty list and wrongly overwrites head on element 2.
  • Element 1: the list is empty (head == NULL), so head and tail both point to the new node.
  • Elements 2 … N: the same two lines every time. tail.next = node links the old tail to the new node, then tail = node moves tail on.
  • The loop stops after element N. Only the song name changes between elements.

Step 3 of 4

Navigating with temp: one next at a time

The kernel says“To navigate, a pointer temp starts at head and follows next until it reaches NULL, so reaching the k-th node takes k - 1 moves”
Kernel check. Accurate. There is no jump straight to position k as in an array: reaching node k costs k − 1 moves.
  • temp is a walking pointer. It starts at head, and temp = temp.next moves it one node on.
  • Reaching node k takes k − 1 moves. A search for a missing song checks every node and stops when temp becomes NULL.
  • Unlike an array there is no index: no way to jump straight to node k.

Step 4 of 4

Deleting a node: relink around it

The kernel says“Deleting a node only changes pointers: the node before it is linked to the node after it”
Kernel check. Needs a qualifier: deleting the first node has no node before it, so head itself moves to head.next. If the deleted node was the tail, tail moves back to the node before it. Finding the node first still takes a walk.
  • To delete a middle node, find the node before it (prev) and set prev.next = cur.next. The orange arc shows the new link.
  • Deleting the first node has no node before it, so head = head.next. Deleting the last node also moves tail back.
  • Only one pointer changes, but finding prev still takes a walk from head.
