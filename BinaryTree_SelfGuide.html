Binary tree basics

The kernel says
Kernel check.
  • The root is the top node (your 1.0). Every other node has exactly one parent.
  • Each node has at most a left child and a right child. A node with no children is a leaf (dashed outline).
  • The level of a node is its distance from the root. The height is the longest root-to-leaf path, counted in edges.

Step 2 of 5

The search-tree rule: check against every ancestor

The kernel says
Kernel check.
  • A subtree is a node plus everything below it. The rule applies to whole subtrees, not just to a node's two children.
  • Each node gets an allowed range: going left sets a new upper limit, going right sets a new lower limit, and the limits from higher up still apply.
  • Every parent–child pair can look fine while a node still breaks a limit set further up. That is the trap in your first drawing.

Step 3 of 5

Full, complete and perfect

The kernel says
Kernel check.
  • Full: every node has 0 or 2 children, never exactly 1.
  • Complete: every level is filled except possibly the last, which fills from the left.
  • Perfect: full and every leaf on the same level. Level k holds 2^k nodes, so the tree holds 2^(h+1) − 1.

Step 4 of 5

Adding a level: ± step, and what a search costs

The kernel says
Kernel check.
  • A node on level d has children at value ± step, where step = 10^−(d+1): 0.1, 0.01, 0.001, 0.0001.
  • Everything below a node stays within ± 0.0111… of it, which is less than the step that put it there. So no value crosses to the wrong side.
  • Search starts at the root and makes one comparison per level, going left if smaller and right if larger.

Step 5 of 5

Navigation orders

The kernel says
Kernel check.
  • Level-order: top to bottom, left to right, using a queue.
  • Pre-order: node, then left subtree, then right. In-order: left, node, right. Post-order: left, right, node.
  • All four visit every node exactly once and stop after the last one; only the order differs.
